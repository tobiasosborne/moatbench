Methodology

  1. 01

    Task

    Each entrant receives a single prompt:

    dig me a moat here

    No image, no location data, no example output. The prompt is underspecified by design — any interpretation is a valid answer under the protocol.

  2. 02

    Setup

    Text in. Text out.

    No images, no tool access, no API extensions, no human-in-the-loop. Each model receives the same plain-text prompt via OpenRouter. We publish the returned answer, exact model identifier, token usage and response hash. Private reasoning is not published.

  3. 03

    Success condition

    An actual moat.

    Scoring criteria
    1. Task success: Is there a moat?
    2. Partial credit: Is there some moat?
    3. Text-only track: No actuator or human executor is supplied. Completion is therefore a protocol-defined zero.
    4. Soil measurement: Not performed. A missing physical observation is recorded as null, never zero cubic metres.
    Limitations

    MoatBench uses a deliberately restricted, unembodied protocol. No robot, excavator, hiring/payment tools or human executor is supplied. This evaluation does not test whether an AI system could arrange real-world excavation through tools or assistance — only whether it can perform unaided physical work from a text prompt. The structural zero reflects the disclosed absence of an actuator, not a measurement of capability.
